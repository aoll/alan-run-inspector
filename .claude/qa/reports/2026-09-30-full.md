## Constats détaillés

### B1 · BUG majeur · « Explain this step » n'a pas de limite de débit propre
- Réf. : F05 « The route goes through … the same Postgres rate limit as starting a run: the (N+1)th call within a minute gets 429 » ; spec › Bricks (Security : « on starting a run and on Explain this step »).
- Repro : compte neuf, lancer 1 run, attendre `Done`, puis `POST /api/explain` avec `{runId, position:1, locale:"en"}` 14 fois de suite.
- Attendu : le (N+1)e appel (N = 10 par défaut) répond 429.
- Observé : 14 réponses 200. Le 429 n'apparaît que si 10 runs ont été démarrés dans la minute (vérifié : après 10 runs, l'explication affiche « Too many requests. Try again in a minute. », 429 sur `/api/explain`, capture `shots/71-explain-ratelimit.png`).
- Cause : `lib/services/explain.ts` réutilise `countRecentRuns`, qui compte des runs créés, pas des appels d'explication. Un lecteur peut donc solliciter l'endpoint sans limite (coût réel en `AI_MODE=live`).
- Fichiers : `app/api/explain/route.ts`, `lib/services/explain.ts`, `lib/dal/runs.ts`.
- Lecture alternative : voir Q3.

### B2 · BUG mineur · L'archive JSON est servie en `application/pdf`
- Réf. : spec › Pages (`GET /api/files/...` = l'archive) ; F03 « the file is valid JSON ».
- Repro : ouvrir un run terminé, `GET` du lien « Download archive » (`/api/files/runs/<userId>/<runId>.json`).
- Observé : 200, `content-type: application/pdf`, corps JSON valide. Le téléchargement par le lien fonctionne (nom `<runId>.json`) mais un accès direct dans le navigateur tente d'ouvrir un PDF.
- Fichier : `app/api/files/[...path]/route.ts` (type en dur hérité du template).

### B3 · BUG mineur · L'archive décrit un run « running » sans décisions
- Réf. : F02 « stores a JSON archive of the run and its steps » ; spec journey 1.7 (télécharger l'archive après revue).
- Repro : terminer un run, rejeter une étape avec note, télécharger l'archive.
- Observé : `run.status` vaut `"running"`, pas de `finishedAt` ni de verdict, toutes les décisions sont `"pending"`, `note: null` (l'archive est prise avant `completeRunJob` et avant toute revue). Fichier de test : `archive-A.json` du scratchpad.
- Fichiers : `lib/services/runs.ts` (`processRun`), `lib/dal/run-jobs.ts` (`getRunArchive`). Voir aussi Q4 (lecture « instantané »).

### B4 · BUG mineur · « Introuvable » : page Next par défaut, en anglais, statut HTTP 200

- Observé : « 404 / This page could not be found. » en anglais sur les deux locales (mélange de langues), sans en-tête ni lien de retour, statut HTTP **200** (le `notFound()` survient après le flush du squelette `loading.tsx`). Aucune fuite d'information (autrui et inconnu sont indiscernables). Captures : `shots/40-B-foreign-run.png`, `40-B-foreign-run-fr.png`, `41-B-bad-id.png`, `54-desktop-dark-en-notfound.png`.

### Q1 · À qualifier · Pré-remplissage de la connexion absent de la configuration locale
- Réf. : spec › Users (« pre-filled on the sign-in page ») et F01 (pré-remplissage « avec `DEMO_PREFILL=true` »).
- Lecture 1 : conforme, le drapeau est volontairement désactivé par défaut (`.env.example`). Lecture 2 : la démo livrée ne remplit pas le compte, donc `DEMO_PREFILL=true` doit figurer dans l'environnement de la démo (Vercel) et dans `.env.local` de développement. Vérifié : avec le drapeau, `demo@example.com` et le mot de passe sont pré-remplis en en et fr, et la connexion arrive sur `/runs` (`/fr/runs`).

### Q2 · À qualifier · Titres et textes de steps figés dans la langue de création
- Observé : en français, la liste affiche « Rename a config option » et « Fix the failing invoice test » pour les runs lancés en anglais ; les steps d'un run gardent aussi la langue de lancement (`shots/22-runs-fr.png`).
- Lecture 1 : voulu (« Scenario titles and step texts exist in both languages », texte enregistré à la création). Lecture 2 : mélange de langues dans une même interface ; le titre pourrait être traduit à l'affichage à partir de `scenario`.

### Q3 · À qualifier · Sens de « the same Postgres rate limit »
- Lecture 1 (retenue pour B1) : une limite par appel, comme pour le démarrage. Lecture 2 : le même compteur de runs partagé, ce qui correspond à l'implémentation actuelle et n'ajoute aucune limite aux appels d'explication.

### Q4 · À qualifier · Corps de `POST /api/explain`
- F05 : `{ stepId, locale }`. Implémentation : `{ runId, position, locale }` (une étape n'a pas d'identifiant propre, elle est adressée par run et position) ; `{stepId, locale}` répond 400. Cohérent avec F04 (mêmes clés) mais écart de lettre avec la spec.
