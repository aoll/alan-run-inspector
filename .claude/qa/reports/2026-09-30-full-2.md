- Fichiers : `app/[locale]/not-found.tsx`, racine de `app/`. Pas de capture (page nue, texte et statut relevés dans `j14.out`).

### Q5 · À qualifier · Échec du stockage de l'archive : aucun retour, aucun retry
- Réf. : F02 « Once the run is `done`, the consumer stores a JSON archive … and records `archiveUrl` ».
- Repro : rendre l'écriture de `.data/files/runs/<userId>` impossible (fichier à la place du dossier), démarrer un run.
- Observé : le run passe à `done` avec ses 8 étapes, mais `archive_url` reste vide : pas de lien « Download archive », aucun message, aucune nouvelle tentative (`failRunJob` ne touche pas un run `done`, une redelivery ne rejoue pas un run `done`) ; l'erreur n'est que dans le journal (`[runs] job failed …`). Les décisions restent possibles (l'archive n'existant pas, `refreshArchive` ne fait rien). De même, un échec de réécriture après une décision n'est journalisé que côté serveur (`review.ts`, volontaire d'après le commentaire) : l'archive téléchargeable reste alors celle d'avant la décision.
- Lecture 1 : acceptable pour une démo (le stockage local ne tombe pas en panne). Lecture 2 : un run `done` sans archive ne peut plus en obtenir, et une archive périmée est servie sans avertissement (critère F03 « the file … containing the steps as reviewed »).
